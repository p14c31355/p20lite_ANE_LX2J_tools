## 主要な確定事実 (一次ソース照合済み)

- SDHCI (eMMC): Arasan @0xFF390000。vendor sdhci_init の ier = 0x007F0007 (0x34 と 0x38 に書く)。
- dw_mmc (SD): base 0xFF37F000。vendor INTMASK = CMD_DONE|DATA_OVER|TXDR|RXDR|ERROR_FLAGS (0xbfc2)。
  TMOUT=0xFFFFFFFF。CTRL.INT_ENABLE 必要。
- sysctrl = /sysctrl@fff0a000。 SD スロット IO 電圧 = SCTRL+0x314、bit2=SEL18 (1.8V)。
  stock は power-up 時 0x101003 (bit2 クリア)、1.8V 切替時 0x101007。
- クロックツリー (DT 解決済み):
  - clk_emmc0 (gate CRG+0x40 bit15) ← muxsys (0xB4 bit2, 1=div分岐) ← div (0xB4[6:3], 2^val)
    ← gate (0xF4 bit1) ← muxpll (0xB4 bit0, 1=AP-PLL3) 。LK 残置 0xB4=0x3F。
  - clk_sd (gate CRG+0x40 bit17) ← muxsys (0xB8 bit6, 0=factor 3.2MHz) ← div (0xB8[3:0])
    ← gate (0xF4 bit3) ← muxpll (0xB8[5:4])。LK 残置 0xB8=0x306 → factor 経路。
- GICD = 0xE82B1000 (カーネル定数)。ISENABLER で供給先を読める。
## 追記 07:15 — eRecovery の正体と恒久対策

- eRecovery = LK の BFM (Boot Fail Monitor) の rescue。LK 本体
  (firmware/fastboot_LK.bin) の文字列で確認: bfm_set_boot_stage /
  bfm_get_bfm_nve_info / nve_increment・nve_decrement /
  bfm_save_log_to_bfi_and_try_to_recovery / rescue_init /
  copy_rescue_image_to_ram / bfm_validate_bfi_partition。
  失敗カウントは NVE (不揮発領域)、ログは BFI パーティション、
  rescue は eRecovery イメージのロード。
- v63 = v62 + パニック→LK fastboot 直行 (PMIC reason=BOOTLOADER → LPM3 NMI
  → SP805、実証済みチェーンを再利用)。以後はクラッシュ→LK→キャッチャー
  再焼の自己修復ループになり、コンボも eRecovery も不要になる見込み。
- 次の一手: eMMC の R/W が可能になったら NVE に成功 stage を早期書き込み
  (失敗カウント自体を止める)。rescue イメージ差し替えは代替手段。
- v61 のクラッシュ真因 = sdhci_cmd の rd32(0x32) (非 4 バイト境界の
  デバイスメモリアクセス)。v62/v63 で rd16 に修正済み。
